
# 使用

[← 返回目录](main.md)



## 1. 启动顺序

```bash
./menu.sh     # 1. 打开统一图形界面，先做设置
./run.sh      # 2. 启动机器人
```

也可以在界面「启动台」页直接点 **启动 QQPilot**，它会替你在项目目录执行 `run.sh`。

启动前请确认：

- 处于 ****X11**** 会话（登录界面选择 “GNOME on Xorg” 等）；[为什么不能是![alt text](ODF.png)Wayland](Wayland.md)
- QQ 已登录；
- 系统显示缩放 100%、QQ 使用浅色主题（见 [安装](install.md#2-安装并设置-qq-for-linux)）。

---

## 2. 一次完整循环

`ScreenshotToUILayout.py` 启动后会做这些事：

1. **定位窗口**：把标题为 `qq` 的窗口移动到左上角，并调整到 `config.ini` 里的 `width` × `height`。
2. **解析坐标**：按 `positions.py` 里的相对坐标，算出聊天列表、聊天区、输入框、发送按钮、上传按钮等的实际位置。
3. **寻找红点**：周期性截图，在聊天列表区域做模板匹配，寻找“有新消息”的红点。
4. **点进会话并框选**：点开红点，按住鼠标在聊天记录上框选，然后 `Ctrl+C` 复制到剪贴板。
5. **解析消息**：`conversationStyleExtract.py` 把聊天文本切成一条条 `ChatContent`（用户名、时间、正文、图片路径），并区分哪些是自己发的。
6. **请求模型**：`answer.py` 把会话拼成请求发给所选后端（Ollama / 内置 / Chat Completion / OneBot），拿到回复文本。
7. **扩展介入**：在“收到消息后”“截图后”“发送前”三个时机调用 `Extensions/` 里的扩展（见 [扩展开发](extensions.md)）。
8. **发送回复**：把回复粘贴进输入框，按 `Ctrl+Enter` 发送；如果答案为空且允许，改为按概率发送一张图片。

之后回到第 3 步继续循环。

---

## 3. 悬浮状态窗

启动后会有一个深色小浮窗贴在屏幕**右下角**，实时显示当前状态：

| 显示内容 | 含义 |
|----------|------|
| 正在初始化 / 初始化完成 | 启动阶段 |
| 正在尝试登录… | `autologin` 打开时 |
| 正在寻找新信息… | 等待新消息 |
| 🚫🖱️ 发现新信息 / 请勿移动鼠标 | 正在自动操作鼠标 |
| 等待语言模型生成答案 | 已发出请求，等回复 |
| 发送消息 🎉 | 回复已发送 |

> **右键点击浮窗可以关闭它**（状态仍会打印在终端）。

浮窗由 `dockLog.py` 实现（tkinter），大小随 `config.ini` 的 `scale` 缩放。

## 4. 停止

- 在运行 `./run.sh` 的终端按 **Ctrl+C**：程序会打印“结束运行”并退出。
- 在图形界面「启动台」页点 **停止**：界面会给子进程发送终止信号。

> 两种方式都会先让 QQ 窗口回到正常状态，不会残留半截输入。

---

## 5. 注意事项

- 🖱️ **运行时不要移动鼠标**：程序靠绝对坐标点击、拖拽，鼠标被挪走会点错位置。
- 🪟 **保持 QQ 窗口可见**：最小化或切走窗口都会让截图拿不到内容。
- 🎞️ **别改界面布局**：换主题、改字体、改缩放、QQ 自动更新都会导致模板匹配失败。
- 🕒 **首次运行会慢**：第一次截图、第一次加载模型都要额外时间。
- 🖼️ **图片**：只有 `isvisionmodel = True` 时才会把图片交给模型；`maximagecount` 控制每次最多几张。
- 📄 **日志**：终端会打印每一步的坐标与结果，排查问题时请保留终端输出。
